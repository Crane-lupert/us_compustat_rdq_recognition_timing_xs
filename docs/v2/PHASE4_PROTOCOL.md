# 4차 — 비슷한 가설의 사전 고정 시험 (공통 지시서, 2026-11-21)

> 공개 사본 (2026-11-25). 원문에서 (i) 같은 규칙으로 진행한 다른 프로젝트의 가설·결과, (ii) 작업 지시 인용과 로컬 폴더 이름을 뺐다. 뺀 자리는 **[생략]** 으로 표시했다. 그 밖의 문장은 원문 그대로다. 문서 안의 경로 (`_main_checks/…`, `RDQ_cadence/…`) 는 작업 폴더 (`RDQ_V2_WORK`) 기준이다.

먼저 `PROTOCOL.md` 와 `PHASE3_PROTOCOL.md` 를 읽는다. 이 문서는 그 위에 얹는 4차 지시다. 편별 사양은 편마다 따로 있다 (이 저장소의 것은 `PHASE4_SPEC.md`). **[생략]**

## 0. 왜 4차를 하는가

**[생략]** (다른 두 프로젝트의 3차 결과). 요청 (2026-11-21): 그 저장소들이 쓴 소재와 이 랩탑에서 쓸 수 있는 소재로 **비슷한 가설이나 신호가 성립하는지** 방법을 찾는다.

4차는 그 후보 가설들의 시험이다. 게시 주장의 재사양이 아니라 **새 가설**이고, 지위는 탐색적 pilot 이다.
- 사양은 결과를 보기 전에 고정했다 (이 문서와 편별 사양, 2026-11-21).
- 같은 가설군에서 앞선 실패를 본 뒤에 고른 후보들이다 (정보 누출 위험). 그래서 통과 기준에 "전·후반 두 구간 모두 같은 부호" 를 넣었고, 통과하더라도 지위는 "사전 고정 pilot 통과" 다.
- 결과가 좋게 나오게 하는 것이 목표가 아니다. 성립하면 어느 조건에서 얼마인지, 성립하지 않으면 그렇다고 확정한다.

## 1. 금지 사항

`PROTOCOL.md` §1 과 `PHASE3_PROTOCOL.md` §1 을 그대로 적용한다. 다시 적는다.

1. 쓰기는 해당 작업 폴더의 `phase4/` 아래에만. 1–3차 산출물과 `phase4/common/` 은 읽기만 한다. 앞 단계 스크립트를 고쳐 써야 하면 `phase4/scripts/` 로 복사해서 고친다. 연구 저장소 (`D:/vscode/<repo>`) 와 다른 로컬 작업 폴더 (공개본에서 이름 생략) 는 읽기 전용이다. `git commit`·push 금지.
2. `.env`, `.pgpass`, 키·설정 파일 (`openrouter-config.yaml` 포함) 을 열지 않는다. `wrds.Connection` 등 WRDS 직접 접속 금지. WRDS 자료는 `E:/wrds-data-courier/output/dump/` 의 로컬 파일만 쓴다 (CCM 링크 테이블 없음 — CUSIP/ncusip 과 유효 기간으로 연결).
3. **유료 LLM API 호출 금지** (4차는 예외 없음). 저장된 라벨만 쓴다.
4. 외부 요청은 공개 자료만 (SEC EDGAR, FRED, ECB, BoE, Ken French 자료실). 요청 헤더는 개인 정보가 없는 일반 문자열 `research-reverify/1.0`, 초당 5회 이하. 403·429 가 나오면 멈추고 보고한다. 연락처를 넣어 우회하지 않는다. 요청에 사용자 이름·이메일·프로젝트 이름을 넣지 않는다.
5. D: 드라이브 여유가 7.7GB 다. 4차의 새 파일은 편당 합계 600MB 이하. 원시 응답 (JSON·HTML) 은 디스크에 쌓지 않고 필요한 필드만 뽑아 저장한다. 기존 캐시를 다시 쓰고, 큰 임시 파일은 끝나면 지운다. dump 의 대용량 `.csv.gz` 는 duckdb 로 필요한 열·행만 뽑는다 (duckdb `memory_limit` 8GB 이하, 임시 디렉터리는 `phase4/tmp/`).
6. 시스템 프로세스 목록을 조회하는 명령을 쓰지 않는다. 거부되는 명령은 우회하지 않는다. 작업 폴더 밖에 디렉터리를 만들지 않는다 (경로에 `C:` 같은 드라이브 문자를 상대 경로로 쓰지 않는다).
7. 사양 탐색 금지. 사양서에 적힌 검정은 **전부** 돌리고 **전부** 보고한다. 사양서에 없는 변형을 돌려 통과 여부를 바꾸지 않는다. 사양서에 없는 분석이 꼭 필요하면 `EXPLORATORY (post hoc)` 로 표시해 따로 적고, 판정에는 쓰지 않는다.

## 2. 절차

**Step 0 — 자료 점검 (결과 변수 계산 전).** 사양서가 지정한 입력의 존재·범위·열 의미를 확인한다. 사양서의 가정과 다르면 (예: 자료 범위, 식별자, 변수 정의) 결과 변수를 계산하기 전에 대안을 정해 Step 1 에 적는다.

**Step 1 — 사양 동결.** 사양서가 정하지 않은 구현상의 선택 (창 경계, 필터, 결측 처리, 계열 ID, 변수 대체) 을 결과 변수 (수익률·발생률·매도 지표의 사건군 평균) 를 계산하기 **전에** `phase4/FROZEN_PARAMS.json` 에 근거와 함께 적는다. 그 뒤에 바꿔야 하면 같은 파일의 `deviations` 배열에 사유와 바꾸기 전·후 결과를 모두 적는다.

**Step 2 — 실행.** 주 검정 → 보조 → 참조 순서. 오래 걸리는 계산은 로그를 `phase4/logs/` 로 돌리고 백그라운드로 실행한다.

**Step 3 — 판정.** 편별 사양서의 통과 기준 (다중검정 보정 임계값 + 전·후반 부호 일치) 을 그대로 적용한다.

## 3. 공통 추론 규칙

`PHASE3_PROTOCOL.md` §3 을 그대로 적용한다 (독립 관측 단위, 단순수익률·상장폐지 수익 포함, 시점 기준 식별자 연결, 공개 뒤 첫 거래 가능 시점 진입, 호가 스프레드 기반 비용, 달력 시간 기준 연환산). 추가:

- 달력 시간 포트폴리오의 요인 회귀는 FF5 + UMD (Ken French 일별·월별), 절편 t 는 Newey–West.
- 임계값은 양측. 예상 부호는 사양서에 적혀 있고, 반대 부호의 유의한 결과는 "성립" 이 아니라 따로 보고한다.
- 판정 등급: **성립** = 주 통계량이 예상 부호로 보정 임계값을 넘고, 사양서의 전·후반 두 구간에서 부호가 같다. **약함** = 예상 부호이고 명목 5% (|t| ≥ 1.96) 는 넘지만 보정 임계값 미달, 또는 임계값은 넘지만 한 구간의 부호가 반대. **성립 안 함** = 그 외.

## 4. 산출물

보고서 파일 (`.md`) 은 쓰지 않는다 (실행 환경이 막는다). 스크립트·로그·CSV·JSON 은 `phase4/` 에 저장하고, 보고서는 최종 답변 텍스트로 돌려준다. `phase4/run_phase4.sh` 한 번으로 전체가 다시 돌아야 한다 (외부 요청 단계는 캐시가 있으면 건너뛴다).

- `phase4/FROZEN_PARAMS.json`
- `phase4/out/results.csv` — 열: `test_id, sample, stat, value` (모든 사전 고정 검정의 n, 추정치, t, 구간별 값)
- 주 검정의 사건 단위·일별 (또는 기간별) 수익률 시계열 parquet — 메인 스레드가 독립 재계산에 쓴다

최종 답변 구성 (한국어):
- **A. 양(+)의 사실 후보** — 통과한 것만. 한 줄 문장 (기간·표본·조건 포함), 근거 수치, 면접에서 공격받을 지점.
- **B. 사전 고정 검정 전체 표** — 검정마다 표본 수, 추정치, t, 전·후반 값, 판정 (성립 / 약함 / 성립 안 함). 통과하지 못한 것도 전부.
- **C. 자료 점검에서 나온 것과 동결 뒤 이탈** — `deviations` 전부.
- **D. 한계** — 표본·식별·비용·선행연구와의 관계에서 결론을 제한하는 것.
- **E. 다음 단계 제안** — 돌리지 않은 것. 유료·대용량 수집이 필요한 것은 비용 추정과 함께.
- **F. 파일 목록과 재현 명령.**

서류 문장의 프레임은 `PHASE3_PROTOCOL.md` §4 의 사용자 지시를 따른다: 서류용으로 권고하는 것은 양(+)의 사실뿐이다. 통과하지 못한 검정은 B 에 사실대로 적되 서류 문장으로 권고하지 않는다.
