# 7차 — RDQ·SEC Letter 조건 변조 탐색, 사전 고정 규칙

> 공개 사본 (2026-11-25). 원문에서 (i) 같은 규칙으로 진행한 다른 프로젝트의 가설·결과, (ii) 작업 지시 인용과 로컬 폴더 이름을 뺐다. 뺀 자리는 **[생략]** 으로 표시했다. 그 밖의 문장은 원문 그대로다. 문서 안의 경로 (`_main_checks/…`, `RDQ_cadence/…`) 는 작업 폴더 (`RDQ_V2_WORK`) 기준이다.

고정일 2026-11-23. 결과 (수익률) 를 보기 전에 썼다. 메인 스레드가 수행하고 산출물은 `_main_checks/phase7/` 에 둔다.

## 0. 사용자 지시와 이 작업의 성격

**[생략]** (작업 지시 인용)

4–6차는 검정마다 사양을 하나씩 고정했다. 이번은 다르다. **조건을 여러 개 바꿔 보는 탐색**이다. 많이 돌리면 우연히 좋아 보이는 조합이 나오므로, 탐색에 쓰지 않은 자료로 한 번 더 검정해 통과한 것만 결과로 보고한다. 탐색에서만 좋았던 것은 결과가 아니다.

지킬 것 (그대로): SEC 에 자동 요청을 보내지 않는다. 유료 LLM 호출 없음. 연구 저장소와 다른 로컬 작업 폴더는 읽기만. WRDS 는 로컬 덤프만. 파일 삭제 없음.

## 1. 자료를 세 구간으로 나눈다

| 구간 | 정의 | 쓰임 |
|---|---|---|
| 탐색 | 진입일 (SEC Letter 는 공개일) 의 연도가 **짝수**이고 2024년 이하 | 조건을 바꿔 가며 본다. 횟수 제한 없음 |
| 확인 | 연도가 **홀수**이고 2023년 이하 | 탐색에서 남긴 후보를 **한 번만** 검정한다. 그 전에는 이 구간의 결과 변수를 계산하지 않는다 |
| 기록 | 2025년 | 확인을 통과한 후보에 대해서만 마지막에 연다. 검정이 아니라 기록이다 (1년치라 검정력이 낮다) |

연도 짝·홀수로 나눈 이유: 두 구간이 달력상 겹치지 않고, 어느 한쪽이 특정 시기 (위기, 최근) 에 몰리지 않는다.

**이미 본 것의 고지.** 4–6차에서 전체 표본 (짝·홀수 해 모두) 으로 본 결과가 있다: R1 과 그 분할 (규모, 5년 구간, 진입일 1·10거래일), R2, R3, RDQ-R, RDQ-I 와 그 분할 (규모, 연차·분기, 기대 간격, 진입일 1·10, 가치가중), RDQ-F (매수·매도 집단별), X1, X1b, X2a, X2b, X3, SEC-D, SEC-N. 이들과 같거나 거의 같은 조건이 후보로 올라오면 "이전에 전체 표본으로 봄" 으로 표시하고, 확인 구간 통과만으로는 결과로 삼지 않는다 (2025년 기록이 같은 방향이어야 한다).

## 2. 무엇을 바꿔 보는가

기준값만 바꾼 것 (며칠 지연, 보유 기간, 규모 구간) 은 이미 발표된 신호의 재현이라, 강하게 나와도 새 발견이 아니다 (portfolio 규칙 L1: 방법의 미세 조정은 novelty 가 아니다). 그래서 **새 정보를 붙이는 조건**을 먼저 돌린다.

### 2.1 **[생략]** (다른 프로젝트 — 가족 S — 의 사건·조건 목록)

그 절에 적혀 있던 통계량 정의는 두 가족에 공통이라 남긴다: (조건 = 1 인 사건의 평균) − (조건 = 0 인 사건의 평균), 연도 고정효과, 월 군집. 연속 변수는 탐색 구간의 3분위로 나눠 상위 대 하위.

### 2.2 RDQ (가족 R)

- 사건 세 종류:
  1. 지연: 기대 발표일을 k 거래일 넘기고 침묵 (k = 1, 3, 5, 10). 기대일은 전년 같은 분기 발표일 + 1년. 결과 변수는 발표 다음 날까지 (최대 40거래일) 의 초과수익과 고정 5·10·20거래일 초과수익.
  2. 발표: 실제 발표일. 결과 변수는 발표 뒤 2–21, 2–61거래일 초과수익. 조건은 발표가 기대일보다 이른·늦은 정도와 아래 변수의 결합.
  3. 기대 구간: 기대 발표일 5거래일 전 진입, 기대일 다음 날 청산.
- 붙이는 조건 (모두 진입 시점에 공개된 것):
  - 직전 분기 실적: 전년 같은 분기 대비 EPS 변화 / 주가 (부호, 3분위), 적자 여부
  - 직전 12–2개월 수익률, 직전 1개월 수익률
  - 규모 순위, 주가, 회계 4분기 여부, 산업 (SIC 1자리)
  - 과거 8개 분기의 지연 횟수, 발표일 규칙성
  - 직전 365일의 NT 제출, 직전 180일의 8-K 4.01 (감사인 교체)·4.02 (신뢰 철회)·5.02 (임원 변동)·2.05–2.06 (구조조정·손상)
  - 직전 180일 내부자 매수·매도 (2015년 이후), 공매도 잔고 비율과 그 변화
  - 최근 공개된 SEC 레터의 유무와 횟수
- 침묵 판정: 8-K 2.02 이력이 있는 기업은 그것으로 확인한다 (이력 범위 밖은 Compustat 발표일만).
- 통계량: 가족 S 와 같다 (조건 = 1 대 0 의 차이, 연도 고정효과, 월 군집). 사건 자체의 평균 초과수익도 함께 낸다.

### 2.3 "조금씩 바꾸기"

탐색 구간 안에서는 위 격자에 없는 조건을 더해도 된다 (기준값을 촘촘히, 두 조건의 결합 등). 더한 것은 `phase7/SEARCH_LOG.md` 에 순서대로 적는다. 확인 구간의 결과는 §3 의 한 번 외에는 보지 않는다.

## 3. 선별과 확인

1. **선별 (탐색 구간).** |t| ≥ 3.0, 조건 = 1 인 사건 200건 이상, 조건 = 0 인 사건 200건 이상. 같은 조건의 인접 기준값·인접 창은 가장 강한 것 하나만 남긴다. 가족별 최대 10개. 돌린 조합의 총수를 적는다.
2. **확인 (확인 구간, 한 번).** 선별한 조합을 그대로 확인 구간에 적용한다. 통과 = 탐색과 같은 부호이고 |t| ≥ 2.58 (후보 10개에 대한 본페로니, 단측 5%).
3. **통과한 것만**: 전체 기간 달력 시간 FF5+UMD 알파, 비용 차감, 2025년 기록, 선행연구 대조 (P8·Stage B), 분류 (새 구성 / 알려진 신호의 기준값 변조).
4. 확인은 한 번뿐이다. 그 뒤에 탐색을 더 하려면 새 확인 표본이 있어야 한다 (2025년 이후 자료).

## 4. 보고

통과하지 못한 것을 포함해 전부 적는다: 돌린 조합 수, 탐색 구간 상위 표, 선별한 후보, 확인 결과. 탐색에서만 좋았던 조합은 "탐색에서만" 이라고 적는다.
